# 05.5 · Graphite only

Makes Graphite (light and dark) the only look. Removes the Classic layout (`Layout::CLASSIC`), the
old themes (Classic, Native, High contrast, Metro, Adwaita, Breeze, Luna, Aero, Aqua), their
drawing code and every asset only they use. The theme system stays, for colour and icon variants
on Graphite's layout. Runs **before 06**, so 06 to 09 are built, checked and screenshotted once.

- Branches, in this order: `ui/05.5a-graphite-icons`, `tools/upstream-sync-graphite-only`,
  `ui/05.5c-classic-removed`
- Needs: 05b merged into `dev`.
- Unblocks: 06 (and every later plan, which no longer gates on `ChromeLook::Graphite`).

## Before each part

- **Screenshots: known gap G1** (`../KNOWN-GAPS.md`). Offscreen captures come out black on the
  maintainer's PC, and the owner accepted PRs without pictures. Each part's PR says "No
  screenshots: see KNOWN-GAPS G1" and carries the logged run's output as its proof. 05.5c's
  pixel comparison (step 9) is replaced by the comparison of the icons reached, before and after,
  until G1 closes. Then the owed pictures are taken.
- **Upstream syncs and 05.5c don't overlap.** Syncs need not be finished: 05.5a and 05.5b run
  alongside them. Only 05.5c clashes, since its deletions and a sync's ports touch the same files.
  - A sync PR open when 05.5c starts merges first.
  - No new sync starts while 05.5c is open.
  - Syncs resume right after 05.5c merges, with 05.5b's rules.
- **No release** (`dev` → `main`) between 05.5c and plan 10. The website and docs still show the
  old looks until plan 10 rewrites them, and the website is published from `main`.
- **Disk:** C: never below 16 GB free. Build into a target of the part's own on E:, cut to what
  the checks need, and delete it after the PR.

## Why

Every UI change was built and checked twice, once per layout, and screenshot checks covered every
theme in light and dark. Plan 05a took 80 pictures and 05b 60 more; with Graphite only, a check
takes about 20. Estimated saving: a quarter to a third of the work on each of 06 to 09, plus
smaller audits and simpler upstream syncs. These are estimates, not measurements. The fork has no
users yet, so nothing needs migrating.

### Classic as the base

- New settings default to `"classic"` (`settings.rs:368`).
- `theme::select` (`theme.rs` about 90-118) gives Classic for an empty id, `"classic"`, or a theme
  that fails to load. It also builds Native.
- `palette::CLASSIC` (`palette.rs:641`) is the base every theme file inherits, Graphite included
  (`graphite.toml` has no `inherits`, see `themefile.rs:398,433`). **It stays**, as Graphite's
  base, and is no longer a theme anyone can choose.
- `palette::builtins()` (`palette.rs:657`) has 9 themes. `native.rs:89,109` uses `builtins()[1]`
  (high contrast).
- View → Theme is built by `theme_menu` (`app.rs` about 6050).

### The two layouts

- `Layout::CLASSIC` and `Layout::GRAPHITE` are in `chrome.rs`; `ChromeLook` is in `palette.rs`.
- `ChromeLook::Classic` and `Layout::CLASSIC` are named 9 times in `chrome.rs` and `palette.rs`.
- The Graphite branches are about 11 in `chrome.rs`, 14 in `list.rs` and 2 in `app.rs` (`g` / `!g`).
- `theme.rs:65` answers which layout is in use.

### Assets

- **Old theme folders:** `crates/app/assets/themes/{metro,adwaita,breeze,luna,aero,aqua}/` (about
  3.6 MB) and their 6 `.toml` files, plus `high-contrast.toml`.
- **Shared icons:** `crates/app/assets/icons/silk` (15 PNG plus `readme.txt`), `tango` (25 × 3 forms
  plus `README.txt`, about 1 MB), `lucide` (17 SVG, `VERSION`, `LICENSE`).
- **Built in:** almost every asset is compiled into the program (`include_bytes!` /
  `include_image!` in `themeicons.rs`, `chrome.rs` `silk()`, `fileicons.rs` `tango!`). Deleting a
  file without its code line breaks the build.
- **Kept:**
  - `icons/app/` (`mdm.ico`, 32/48/256 PNG: window, tray, About, title bar, installer);
  - `fonts/geist`;
  - `themes/graphite/`, `graphite.toml`;
  - `crates/geo/data/flags.png`.
  
  `icons/app/` 16/20/24/64/128 PNG are read by nothing, but `tools/icon/build_icon.py` writes them:
  left for plan 10's logo work.

### Upstream sync

- `tools/upstream-sync/sync.py` sorts by comparing the fork point with the fork's `dev`. A file
  deleted in the fork counts as gone. A deleted file 90 % alike to an added one counts as moved,
  and 50 to 90 % alike as rewritten (`fork_state`, `Fork.is_gone`, `sort_commit`).
- A scratch test of this removal: metro's `icons/LICENSE` pairs with Graphite's `icons/LICENSE` at
  96 % (both MIT texts) and would count as **moved**. Two consequences:
  - an upstream change to metro's licence would sort `clean` onto Graphite's licence;
  - `metro/` would stay alive as a folder, so a new upstream file there would sort `clean` and
    bring the folder back.
- Today Graphite's licence already pairs with `assets/flags/LICENSE` at 60 % (rewritten).
- The theme `.toml` files pair with nothing.
- Git's rename limit is not reached: about 1,500 deletions against 404 additions.
- Upstream added a theme, Emerald (`8742fcd8`), which uses Metro's icons. Today it sorts `port`, 8
  files.
- In the 56 upstream commits since the fork, it is the only one that touched the themes.

## 05.5b · Upstream sync ready for the removal (`tools/upstream-sync`)

Lands before 05.5c, so the first `status` after the removal sorts correctly.

1. **Licence texts are never a move** (`sync.py` `fork_state`): a rename whose source and
   destination are both licence or notice files is not counted as a move or a rewrite. The source
   then counts as gone. The files are `LICENSE*`, `COPYING*`, `AUTHORS*`, `README.txt`,
   `readme.txt` and `SOURCES.txt`.
   - Test in `test_sync.py`: a fork deletes `themes/x/icons/LICENSE` and adds a near-identical
     `themes/graphite/icons/LICENSE`. An upstream change to the first sorts `removed`, and a new
     upstream file under `themes/x/` sorts `removed`.
   - It fails without the fix.
2. **A note for theme commits:** a commit that adds or changes a theme other than Graphite
   (`crates/app/assets/themes/<id>.toml` or `<id>/`, `<id>` not `graphite`) gets the note "a theme
   other than Graphite: this fork keeps Graphite only (plan 05.5): skip". Test it.
3. **The skill** (`.claude/skills/upstream-sync/SKILL.md`):
   - Step 4 gains a fourth group: fixes that apply only to the Classic layout, an old theme,
     Native or high contrast, and **every new theme**, are `skipped` with the note "Graphite only".
   - Step 6's line "A port into Graphite's files (crates/app/src)" becomes: the app's interface is
     Graphite's alone, so a port changes Graphite's code; say which window.
   - "Never" gains: never bring back a removed theme, the Classic layout, or Silk, Tango or Lucide
     icons.
4. **Before** 05.5c merges: save `python tools/upstream-sync/sync.py status --all --json` to the
   PR.
5. **After** it merges: run `status --fetch` again and compare.
   - Old-theme-only commits must now sort `removed`.
   - Emerald (`8742fcd8`) must carry the theme note.
   - Record it `skipped --note "a theme; Graphite only (plan 05.5)"` in the next sync run, with any
     `deferred` rows that were only about old themes.
6. Checks: `python tools/upstream-sync/test_sync.py`, and `sync.py doctor`.

## Risks

- **Windows high contrast:** with Native and High contrast gone, it no longer changes the app's
  colours until the deferred work lands. Record it in the PR and ROADMAP.
- **Hidden Classic paths:** a code path the audits and runs didn't open. The compiler finds most
  of them once `ChromeLook` is gone. The final check's extra runs cover the fallbacks.
- **Upstream ports in `crates/app/src` get harder:** a fix in Classic-only code becomes `port`, to
  be read and usually skipped. 05.5b's skill rule makes that a quick decision.
- **Size:** 05.5c deletes far more than it adds. If its diff passes about 1,500 changed code
  lines, not counting deleted assets, split it into code (layout, themes) and assets (folders,
  attribution) as 00 says.
